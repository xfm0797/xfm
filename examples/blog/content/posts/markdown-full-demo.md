这篇是语法样本，不是教程。每一节都先放「写法」（代码块），紧接着是「实际效果」——效果就是把同一段 Markdown 真的渲染出来，所以你在右侧看到的样子，就是源码跑出来的样子。

想查具体某一种写法，看左侧目录直接跳。

## 标题：ATX 与 Setext

一到六级都用井号，井号与文字之间要有一个空格：

```markdown
# 一级标题
## 二级标题
### 三级标题
#### 四级标题
##### 五级标题
###### 六级标题
```

另外支持 Setext 写法——段落下面加一行等号或减号（老式 Markdown 的风格，只有两级）：

```markdown
一级标题
========

二级标题
--------
```

实际效果（这里降级展示，避免和正文标题打架）：

#### 四级标题

##### 五级标题

## 段落、换行与强调

连续的行会合并成同一段，空行才分段。段落里单个换行不会产生 `<br>`，这一点和 CommonMark 一致：

```markdown
这是第一行，
这是同一段的第二行。

空行之后才是新段落。
```

这是第一行，
这是同一段的第二行。

空行之后才是新段落。

强调有四种写法，都可以嵌套：

```markdown
**加粗**　*斜体*　_也是斜体_　~~删除线~~
**加粗里嵌 *斜体* 也成立**
行内代码：`const a = 1`
```

**加粗**　*斜体*　_也是斜体_　~~删除线~~
**加粗里嵌 *斜体* 也成立**
行内代码：`const a = 1`

## 链接

四种写法，效果一样：行内、引用式（带标签）、引用式（简写）、自动链接。

```markdown
见 [行内写法](https://example.com "可选的标题")。
见 [引用式写法][xfm] 和简写 [xfm]。
自动链接写 <https://example.com>，裸 URL 也行：https://example.com/docs。

[xfm]: https://example.com/docs "文档"
```

见 [行内写法](https://example.com "可选的标题")。
见 [引用式写法][xfm] 和简写 [xfm]。
自动链接写 <https://example.com>，裸 URL 也行：https://example.com/docs。

外部链接会自动加 `target="_blank"` 与 `rel="noopener"`，站内链接保持当前窗口——这条不用手写属性，引擎按 `href` 判断。

## 图片

和链接同形，前面多一个感叹号。图片会自动带 `loading="lazy"` 与 `decoding="async"`，长文里不会拖慢首屏：

```markdown
![替代文字](/assets/logo.png "可选的图注")
![引用式图片][shot]

[shot]: /assets/logo.png
```

因为示例站没有放图片资源，这里只贴写法，不贴效果。

## 列表

无序列表三种符号等价，可以随手混用；有序列表保留起始编号：

```markdown
- 第一项
- 第二项
  - 嵌套子项（缩进两格）
    - 再嵌一层
1. 有序项
2. 有序项
```

- 第一项
- 第二项
  - 嵌套子项（缩进两格）
    - 再嵌一层
1. 有序项
2. 有序项

从任意数字开始都行，编号接着往下排：

```markdown
3. 第三步
4. 第四步
```

3. 第三步
4. 第四步

任务列表用方括号，勾选状态只影响显示：

```markdown
- [x] 已完成
- [ ] 待办
```

- [x] 已完成
- [ ] 待办

### 松散列表

项与项之间空一行，整个列表变成「松散」的——每个项外面补一层 `<p>`，行距会松一些，适合每项都写着成段文字的清单：

```markdown
- 第一项，说明比较长，单独成段更好读。

- 第二项，同样是一小段话。

- 第三项。
```

- 第一项，说明比较长，单独成段更好读。

- 第二项，同样是一小段话。

- 第三项。

不空行的紧凑列表不会补 `<p>`，所以短清单不会莫名其妙被撑开。

## 引用块

引用可以续行、可以偷懒不写 `>`、也可以嵌套：

```markdown
> 第一层引用
> 还是第一层
>
> > 第二层引用
>
> 回到第一层
```

> 第一层引用
> 还是第一层
>
> > 第二层引用
>
> 回到第一层

引用里同样能放列表和代码：

```markdown
> 示例代码：
>
> ```js
> const a = 1;
> ```
```

> 示例代码：
>
> ```js
> const a = 1;
> ```

## 代码

围栏代码块用三个反引号或三个波浪线，语言标记决定高亮。内置高亮覆盖：`js` `ts` `jsx` `tsx` `java` `c` `cpp` `csharp` `go` `rust` `swift` `kotlin` `scala` `php` `json` `python` `bash` `yaml` `html` `css` `markdown`。

````markdown
```js
const greet = (name) => `你好，${name}`;
```
````

```js
const greet = (name) => `你好，${name}`;
```

没有语言标记就不高亮，但照样保留空白与缩进。不想写围栏时，行首缩进四个空格（或一个 tab）也是代码块：

```markdown
    $ xfm build
    $ xfm dev
```

    $ xfm build
    $ xfm dev

行内代码用反引号，内容里的 Markdown 不解析：`**这不会加粗**`、`<div>`。

## 表格

GFM 表格，第二行的分隔线决定对齐方式：

```markdown
| 左对齐 | 居中 | 右对齐 |
| :----- | :--: | -----: |
| 内容   | 内容 |   1,024 |
| **加粗** | `代码` | [链接](/about/) |
```

| 左对齐 | 居中 | 右对齐 |
| :----- | :--: | -----: |
| 内容   | 内容 |   1,024 |
| **加粗** | `代码` | [链接](/about/) |

单元格里的行内语法照常生效，只是不能跨行、不能放块级内容。

## 容器

`:::` 用来写提示框，第一行的第二个词是类型，后面跟标题。类型有 `tip`、`info`、`warning`、`danger`、`details`：

```markdown
::: tip 小技巧
按 Ctrl+K 可以直接搜全文。
:::

::: warning 注意
构建前记得先 `npm i`。
:::
```

::: tip 小技巧
按 Ctrl+K 可以直接搜全文。
:::

::: warning 注意
构建前记得先 `npm i`。
:::

::: info
类型可以省略，默认是 info。
:::

::: danger 危险
这条路径会覆盖已有文件，加 `--force` 前先确认。
:::

::: details 点开看细节
`details` 类型适合放折叠内容，标题就是外面那一行。
:::

## 脚注

正文里写 `[^标记]`，任意位置（段落开头）写定义。编号按首次引用顺序排，每个引用都有回链，全部集中到文末。[^demo]

[^demo]: 这一段就是脚注内容。

    缩进四格可以放块级内容，比如下面这个列表：

    - 第一项
    - 第二项

脚注里的块内容要缩进四格（或一个 tab）；一到三格的普通行算同一段的续行，不会变成新段落。

## 转义

想输出 Markdown 符号本身，前面加反斜杠：

```markdown
\*这不是斜体\*
\`这不是代码\`
\# 这不是标题
```

\`这不是代码\`

## 原始 HTML

块级 HTML 原样输出——只要这一行以标签开头，整块就交给浏览器：

```html
<details>
<summary>点开</summary>

折叠区里仍然是 Markdown，会正常渲染。

</details>
```

<details>
<summary>点开</summary>

折叠区里仍然是 Markdown，会正常渲染。

</details>

但**行内 HTML 会被转义**：段落中间的 `<kbd>` 会显示成 `&lt;kbd&gt;` 而不是按键样式。想在段落里用内联标签，只能把整段写成块级 HTML。

## 锚点与目录

每个标题自动生成 id：`## 锚点与目录` 的锚点是 `#锚点与目录`，中文直接保留，重复的标题自动加序号（`修复`、`修复-1`）。文章页左侧的目录就是按这些标题生成的，滚动时跟随阅读位置高亮。

## 六条容易踩的边界

这些不是缺陷，是规范本身的要求，但都很容易让人以为「渲染坏了」：

1. **引用定义只在段首生效。** 一段话中间写 `[a]: /url` 只是普通文字，不会注册成引用。定义前后各留一个空行最稳。
2. **段落行首以 `<` 开头会被当成 HTML 块。** 比如用 `<https://example.com>` 起头，整行会原样输出。自动链接要么写在句子中间，要么前面加文字。
3. **行内 HTML 转义，块级 HTML 不转义。** 这是有意为之：块级 HTML 是有用的逃生口，行内 HTML 转义能避免正文里的尖括号把版面搞乱。
4. **列表里缩进代码块要看空格数。** `-     code`（标记后五个空格）是项首代码块；`-    code`（四个空格）只是缩进，仍然是段落文字。规范里 1–4 个空格算缩进、5 个以上只算一个、其余属于内容。
5. **缩进代码不能打断段落。** 段落下面紧跟四空格缩进行（中间没有空行）是同一段的续行，不是代码块。
6. **空行之后的续行必须缩进到位。** 空行前可以偷懒不缩进（惰性续行），空行后不行——`- a` 换行空行再写 `第二段` 不缩进，会被判成列表外的段落。

## 小结

上面这些写法全部在这个站点上真实生效——这篇本身就是构建产物，看到什么就是渲染器支持什么。如果发现某段写法与效果对不上，多半是上面六条边界之一。
